# Alpaca equities implementation plan

**Goal:** Add a separately runnable US equities paper trading application with a local dashboard.
**Architecture:** Keep the CCXT-based crypto engine separate. Use Alpaca REST for account, assets, clock, daily bars, positions and orders. Start with an explicitly enabled, long-only daily moving-average example and a fixed paper endpoint. No credentials means a useful setup page, never fabricated account data.
**Tech Stack:** Python standard library; unittest; HTML/JavaScript.

1. Write isolated tests for signals, closed markets, pending orders, asset validation, exposure limits and duplicate submissions. Run them before implementation.
2. Add paper-only REST client and serialized strategy cycle. Use deterministic client order IDs and broker reconciliation; never retry ambiguous writes automatically.
3. Add localhost dashboard with read-only account data and explicit strategy cycle action protected by a random session token and origin checks.
4. Document credentials, startup, scope and limitations; test HTTP server and broker behavior with a local fake.
5. Run tests and a local HTTP smoke check. Broker acceptance requires user-provided paper credentials and must be reported separately.

Scope: US equities, regular session, daily completed bars, integer shares, long only. FreqUI, FreqAI, Freqtrade strategies and backtesting are not automatically supported by this separate engine. No live-money endpoint.
